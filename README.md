# Coffee Tale

โปรเจกต์วิชา Object-Oriented Programming — ระบบสั่งกาแฟด้วยตัวเอง (self-order) แบบเว็บแอป
สร้างด้วย **Next.js 16 + React 19 + TypeScript**

## ปัญหาที่โปรเจกต์นี้แก้

ไอเดียมาจากเวลาไปร้านกาแฟแล้วเจอปัญหาเดิม ๆ ตอนสั่งที่เคาน์เตอร์:

- ชื่อเมนูเป็นภาษาอังกฤษยาว ๆ จำไม่ได้ สุดท้ายต้องชี้ป้ายเมนูแล้วอธิบายกันอยู่นาน เสียเวลาทั้งลูกค้าและพนักงาน
- อยากปรับแต่งหลายอย่าง เช่นหวานน้อย เพิ่มช็อต ใส่วิปครีม แต่พอต้องพูดสดทีเดียวหลายข้อก็กลัวพูดตกหล่น หรือพนักงานจดไม่ครบ
- ร้านคนเยอะ เสียงเครื่องชงกับเสียงคนคุยดังจนพนักงานฟังไม่ชัด ได้ของไม่ตรงกับที่สั่งบ่อย ๆ
- บางคนไม่ค่อยมั่นใจเวลาต้องพูดสั่งเอง โดยเฉพาะตอนมีคิวยาวรออยู่ข้างหลัง
- อยากเห็นราคารวมก่อนตัดสินใจ ว่าเพิ่มท็อปปิ้งหรือเปลี่ยนขนาดแล้วแพงขึ้นเท่าไหร่ ไม่อยากถามพนักงานทีละอย่าง
- ต่อคิวสั่งนานกว่าเวลาชงจริงเสียอีก ทั้งที่รู้อยู่แล้วว่าจะสั่งอะไร
- จ่ายเงินแล้วไม่รู้ว่าต้องรอเรียกชื่อหรือเรียกอะไร ต้องคอยฟังตลอด

Coffee Tale ให้ลูกค้าเลือกเมนูจากรูปจริง ปรับแต่งเองทีละขั้น เห็นราคาเปลี่ยนตามทันที แล้วได้เลขคิวไว้รอรับของ ฝั่งร้านก็ได้ออเดอร์ที่ตรงกับที่ลูกค้าเลือกเป๊ะ ๆ

## ฟีเจอร์หลัก

### ฝั่งลูกค้า

- **หน้าเมนู 3 หมวด** — เครื่องดื่ม / อาหาร / เบเกอรี่ พร้อมรูปภาพจริงทุกเมนู (เมนูตั้งต้น 15 รายการ)
- **ปรับแต่งเครื่องดื่มได้ 4 อย่าง** ราคาคำนวณใหม่ทันทีทุกครั้งที่เลือก
  - ขนาด: S (+0) / M (+15) / L (+30)
  - อุณหภูมิ: ร้อน / เย็น
  - ความหวาน: 0% / 25% / 50% / 75% / ปกติ (100%)
  - ท็อปปิ้ง (เลือกได้หลายอย่าง): เพิ่มช็อต (+20), เพิ่มนมสด (+15), วิปครีม (+15), ไซรัปวานิลลา (+15)
  - ค่าเริ่มต้นคือ S / เย็น / ปกติ / ไม่มีท็อปปิ้ง
- **อาหารและเบเกอรี่** — เลือกจำนวนแล้วเพิ่มลงตะกร้าได้เลย
- **ตะกร้า** — เพิ่ม / ลด / ลบสินค้า แสดงราคาต่อหน่วย ยอดต่อรายการ และยอดรวม
  - สั่งเมนูเดิมที่ตัวเลือกเหมือนกันทุกอย่างซ้ำ จะรวมเป็นรายการเดียวแล้วเพิ่มจำนวนให้อัตโนมัติ
  - กดเพิ่มลงตะกร้ารัว ๆ ไม่ได้ของซ้ำ (กันดับเบิลคลิก)
- **ชำระเงิน (checkout)** — กรอกชื่อลูกค้า (จำเป็น) แล้วเลือกวิธีจ่าย
  - เงินสด หรือ พร้อมเพย์ / QR — **ทั้งสองวิธีได้เลขคิวเหมือนกัน** (เลขคิวไม่ซ้ำกันแม้เปิดหลายแท็บ)
  - QR ได้เลข Ref เพิ่ม และ**ต้องแนบสลิปโอนเงิน**ก่อนถึงจะกดยืนยันได้ ระบบตรวจว่าเป็นไฟล์รูปภาพจริง (ไฟล์อื่นถูกปฏิเสธ) แล้วย่อรูปเก็บไว้กับใบเสร็จ
- **ใบเสร็จ** (`/receipt/[id]`) — เลขคิว รายการพร้อมตัวเลือก ยอดรวม วิธีจ่าย เลข Ref และรูปสลิป (ถ้าจ่ายด้วย QR)
- **หน้า 404 และหน้า error เป็นภาษาไทย** — และถ้าเปิดลิงก์เมนูหรือใบเสร็จที่ไม่มีอยู่ จะขึ้นข้อความแจ้งพร้อมปุ่มกลับหน้าเมนู

### ฝั่งแอดมิน (`/admin`, รหัส `grind123`)

ลิงก์เข้าแอดมินไม่แสดงในหน้าลูกค้า พนักงานเข้าได้โดยพิมพ์ `/admin` ต่อท้าย URL

- **จัดการเมนูครบ (CRUD)** — เพิ่ม / แก้ไข / ลบเมนู
  - ลบเมนูมีข้อความยืนยันก่อนทุกครั้ง
  - ตรวจข้อมูลก่อนบันทึก: ชื่อต้องไม่ว่าง ราคาต้องเป็นตัวเลขตั้งแต่ 1 บาทขึ้นไป (ทศนิยมจะถูกปัดลง)
  - เปลี่ยนหมวดของเมนูได้ (เช่นเครื่องดื่ม → อาหาร) ระบบสร้างเป็นคลาสใหม่ตามหมวดให้เอง
  - แก้หรือลบเมนูแล้ว รายการในตะกร้าที่อ้างถึงเมนูนั้นถูกปรับตามอัตโนมัติ
- **เปลี่ยนรูปสินค้า** ได้ 2 ทาง — วาง URL รูป หรืออัปโหลดจากเครื่อง (ย่อเป็นไม่เกิน 480px ให้อัตโนมัติ) ถ้ารูปเปิดไม่ได้จะแสดง emoji ของเมนูแทน
- **ประวัติออเดอร์** — ดูทุกออเดอร์พร้อมรายการ ตัวเลือก ยอดรวม เลข Ref และรูปสลิป
  - ออเดอร์ใหม่ทุกใบเริ่มต้นเป็น **"ยังไม่ได้ทำ"** เสมอ กดที่ป้ายสถานะเพื่อสลับเป็น **"✅ เสร็จเรียบร้อยแล้ว"** หรือกลับเป็น "ยังไม่ได้ทำ" ได้
  - สีกล่องบอกสถานะ: **เขียว = เสร็จแล้ว**, โทนครีม/เหลืองอำพัน = ยังไม่ได้ทำ
  - ตอนเปิดแท็บประวัติออเดอร์ ออเดอร์ที่ยังไม่ได้ทำอยู่บนสุด (ใหม่ก่อน) ส่วนที่เสร็จแล้วอยู่ล่างสุด — แต่กดสลับสถานะแล้วการ์ดจะอยู่ที่เดิม ไม่เลื่อนหนีจากใต้เมาส์ กันกดโดนออเดอร์อื่นโดยไม่ตั้งใจ
- **โหมดแอดมินสั่งซื้อสินค้าไม่ได้** — ปุ่มตะกร้าใน Header ถูกซ่อน ปุ่มเพิ่มลงตะกร้าถูกปิด และหน้าตะกร้า / หน้าชำระเงินถูกบล็อก ต้องออกจากระบบก่อนถึงจะสั่งซื้อได้

### การเก็บข้อมูล

- ข้อมูลทั้งหมด (เมนู ตะกร้า ออเดอร์ สลิป สถานะแอดมิน เลขคิว) เก็บใน **localStorage ของเบราว์เซอร์** ไม่มี server หรือฐานข้อมูล
- เปิดหลายแท็บในเบราว์เซอร์เดียวกัน ข้อมูลซิงค์กันให้อัตโนมัติ

### ข้อจำกัดที่รู้อยู่แล้ว

- ข้อมูล**ไม่ซิงค์ข้ามอุปกรณ์หรือข้ามเบราว์เซอร์** — ลูกค้าและแอดมินต้องใช้เบราว์เซอร์เดียวกันบนเครื่องเดียวกัน (เหมาะกับการเดโมแบบตู้สั่งอาหาร)
- ล้างข้อมูลเบราว์เซอร์ (clear site data) แล้วข้อมูลทั้งหมดหายไปด้วย
- localStorage มีพื้นที่จำกัด (ปกติราว 5MB) รูปสลิปและรูปที่อัปโหลดกินพื้นที่มากที่สุด ถ้าเต็มระบบจะไม่ล่ม แต่ข้อมูลใหม่อาจบันทึกไม่ได้
- รหัสแอดมินตรวจฝั่งเบราว์เซอร์ จึงเป็นระบบสำหรับเดโม ไม่ใช่ระบบความปลอดภัยจริง
- QR ในหน้าชำระเงินเป็น QR จำลองสำหรับเดโม ไม่ได้เชื่อมกับระบบธนาคารจริง

## แนวคิด OOP ที่ใช้

คลาสทั้งหมดอยู่ใน `src/lib/models/` มีทั้งหมด **10 คลาส**:
`MenuItem`, `Drink`, `FoodItem`, `BakeryItem`, `OrderLine`, `Order`, `PaymentMethod`, `CashPayment`, `QRPayment`, `QueueCounter`

- **Encapsulation** — ฟิลด์เป็น `private` / `protected` ภายนอกอ่านผ่าน getter เช่น `getName()`, `getBasePrice()`
  - ฟิลด์ของ `MenuItem`, `Order`, `OrderLine` เป็น `private` ส่วน `PaymentMethod.counter` เป็น `protected` ให้คลาสลูกใช้ได้
  - `Order` มีเมธอด `private assertEditable()` กันไม่ให้แก้ออเดอร์ที่ชำระแล้ว
- **Inheritance** — มี 2 สาย
  ```
  MenuItem ──┬── Drink
             └── FoodItem ── BakeryItem      (สืบทอด 2 ชั้น)

  PaymentMethod ──┬── CashPayment
                  └── QRPayment
  ```
- **Polymorphism**
  - `getPrice()` — `Drink` คิดราคาจากขนาดและท็อปปิ้ง, `FoodItem` คืนราคาฐาน และ `BakeryItem` ใช้ `getPrice()` ที่สืบทอดมาจาก `FoodItem` — `OrderLine` เรียก `getPrice()` ได้โดยไม่ต้องรู้ว่าเป็นคลาสไหน
  - `confirm()` / `getLabel()` — `CashPayment` และ `QRPayment` ทำงานต่างกัน (QR สร้างเลข Ref เพิ่ม) ส่วน `Order.checkout(payment: PaymentMethod)` เรียกผ่านคลาสแม่
- **Abstract class** — `MenuItem` (มี `abstract getPrice()` และเป็น generic `MenuItem<TOptions>` ให้คลาสลูกกำหนดชนิดตัวเลือกเอง) และ `PaymentMethod` (มี `abstract confirm()` / `abstract getLabel()`)
- **Composition** — `Order` ประกอบด้วย `OrderLine` หลายรายการ และ `OrderLine` เก็บ**สำเนา** options ของตัวเอง ไม่ mutate ข้อมูลต้นทาง (getter ก็คืนสำเนาเช่นกัน)
- **Singleton** — `QueueCounter` มี `private constructor()` เรียกใช้ผ่าน `QueueCounter.getInstance()` เท่านั้น ใช้ออกเลขคิว และใช้ Web Locks API กันเลขคิวซ้ำเมื่อเปิดหลายแท็บพร้อมกัน

## วิธีรัน

### สิ่งที่ต้องมี

- **Node.js 20.9.0 ขึ้นไป** — เป็นขั้นต่ำที่ Next.js 16 กำหนด (โปรเจกต์นี้ไม่ได้ระบุเวอร์ชันไว้เอง)
- **แนะนำ Node.js 22 LTS หรือ 24 LTS** (เป็นคำแนะนำ ไม่ใช่ข้อบังคับของโปรเจกต์ — โปรเจกต์ทดสอบจริงบน Node.js 24.15.0 / npm 11.12.1)

### วิธีที่ 1: `start.bat` (Windows เท่านั้น)

ดับเบิลคลิกไฟล์ `start.bat` ที่โฟลเดอร์โปรเจกต์ สคริปต์จะ:

1. ตรวจว่าเครื่องมี Node.js — ถ้าไม่มีจะแจ้งให้ไปติดตั้งจาก https://nodejs.org แล้วหยุด
2. ถ้ายังไม่มีโฟลเดอร์ `node_modules` จะรัน `npm install` ให้อัตโนมัติ (เฉพาะครั้งแรก)
3. รัน dev server ที่ port 3000 (`npm run dev -- -p 3000`)
4. รอจนเซิร์ฟเวอร์พร้อม (สูงสุด 60 วินาที) แล้วเปิดเบราว์เซอร์ไปที่ http://localhost:3000 ให้เอง

ต้องเปิดหน้าต่างนั้นค้างไว้ระหว่างใช้งาน ปิดหน้าต่าง (หรือกด Ctrl+C) เมื่อต้องการหยุด ถ้าขึ้น error ให้ตรวจว่ามีโปรแกรมอื่นใช้ port 3000 อยู่หรือไม่

### วิธีที่ 2: คำสั่ง npm (ใช้ได้ทุก OS)

ติดตั้ง dependencies (ครั้งแรกครั้งเดียว):

```
npm install
```

โหมดพัฒนา (dev):

```
npm run dev -- -p 3000
```

โหมด production (build ก่อนแล้วค่อย start):

```
npm run build
npm start
```

`npm start` ใช้ port 3000 เป็นค่าเริ่มต้น (เปลี่ยนได้ด้วย `npm start -- -p <port>`)

### เข้าใช้งาน

- หน้าลูกค้า: http://localhost:3000
- หน้าแอดมิน: http://localhost:3000/admin — **รหัสผ่านสำหรับทดสอบ: `grind123`**

```
npm run typecheck   # ตรวจ types ด้วย TypeScript (tsc --noEmit)
npm run lint        # ตรวจโค้ดด้วย ESLint

```

## โครงสร้างไฟล์หลัก

```
src/
├── app/                      # หน้าเว็บ (Next.js App Router)
│   ├── page.tsx              # หน้าเมนู 3 หมวด
│   ├── item/[id]/            # หน้ารายละเอียด / ปรับแต่งเมนู
│   ├── cart/                 # ตะกร้า
│   ├── checkout/             # ชำระเงิน (เงินสด / QR + แนบสลิป)
│   ├── receipt/[id]/         # ใบเสร็จ
│   ├── admin/                # แผงแอดมิน (จัดการเมนู + ประวัติออเดอร์)
│   ├── not-found.tsx         # หน้า 404
│   ├── error.tsx             # หน้า error
│   ├── layout.tsx            # layout หลัก + Header
│   └── globals.css           # สไตล์ทั้งเว็บ
├── components/               # Header, MenuImage, DrinkCustomizer, MockQr, AdminOrderBlock
└── lib/
    ├── models/               # คลาส OOP ทั้ง 10 คลาส + types
    ├── store/                # StoreProvider (React context) + catalogStore (บันทึกเมนูลง localStorage)
    ├── data/menu.ts          # เมนูตั้งต้น 15 รายการ
    ├── format.ts             # จัดรูปแบบราคา / วันที่
    ├── image.ts              # ย่อรูปก่อนเก็บ
    └── hydration.ts          # ตัวช่วยรอโหลดข้อมูลจาก localStorage
public/menu/                  # รูปเมนูตั้งต้น (.jpg)
start.bat                     # สคริปต์เปิดร้านด้วยคลิกเดียว (Windows)
```
